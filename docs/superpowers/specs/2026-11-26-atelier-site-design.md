# Atelier — второй сайт Максима Кухто: дизайн-спецификация сборки

Дата: 26.11.2026. Заказчик: Максим Кухто. Исполнитель: webdev.
Источник визуального языка: «Теоретическая база и дизайн-код сайта kukhto.is-a.dev
в эстетике визионерского архитектурного авангарда» (далее — **док**, 20,7 тыс. токенов,
передан в чат 26.11.2026). Док — источник чисел; при расхождении побеждает док.

## 1. Задача и зачем

Сделать второй личный сайт — «чертёжное бюро»: инженерное портфолио, собранное из
графической грамматики бумажного архитектурного авангарда (Леонидов, Лисицкий, Татлин,
Булле, Фридман, Таут, Ваксман, Отто, Феррис, Фуллер, Солери, Вудс). Сайт живёт
**параллельно** с LCARS-консолью: консоль остаётся на `kukhto.is-a.dev` и не трогается.

Зачем именно так: консоль говорит языком вымышленного интерфейса, atelier — языком
чертежа. Один и тот же набор фактов (14 проектов с измеренными метриками) читается
двумя разными способами, и это само по себе доказательство инженерной аккуратности:
одни данные, две системы представления, обе проверяемые.

## 3. Цели

1. Статический сайт из 6 слотов на `https://kukhtik.github.io/atelier/`, RU в корне,
   EN в `/en/`, полностью на реальном контенте из `site-full.json`.
2. Четыре графических носителя (`void`, `cyanotype`, `chiaroscuro`, `vellum`) с
   автоматическим выбором по `prefers-color-scheme` и ручным переключением в штампе.
3. Реестр 14 проектов как чертёжных планшетов: индекс, статус зрелости, носитель
   метрик, процедурная планометрическая схема; внутри — досье с переключателем
   «Конструктив / Контекст».
4. Ноль растровых изображений. Вся графика — CSS, SVG, генерация при сборке.
5. Машинная приёмка: контраст по каждому носителю, отсутствие переполнения на 1440 и
   390, бюджет веса, отсутствие внешних ресурсов, видимый фокус, `prefers-reduced-motion`.
6. Доказательство — рендер: скриншоты desktop 1440×900 и mobile 390×844 по всем
   носителям + измеренные числа.

## 4. Не-цели (v1)

- WebGL / Three.js, шейдерная дисперсия Таута, сцена на главной.
- View Transitions API, scroll-driven линейка масштаба, любые scroll-анимации.
- Раздел «Заметки» (04): текстов нет — раздел не публикуется, слот остаётся в контенте.
- Тёмная/светлая «тема» в обычном смысле — вместо неё переключатель носителя.
- Клиентский роутер, сборка через сборщик с зависимостями, внешние CDN-шрифты.
- Правки LCARS-консоли и репозитория `kukhtik.github.io`.

## 5. Анти-цели (провал, даже если технически работает)

- Документальные фотографии зданий, «состаренная бумага», красные клинья и лозунги —
  агитплакатная стилизация вместо пространственной инженерии.
- Перехват прокрутки: смена скорости, инерции, направления, обязательный scroll-snap.
- Стеклянные панели с нечитаемым текстом, параллакс без выключателя.
- Придуманные метрики, годы, статусы, «клиенты» — любое число без источника.
- Заимствованный шаблон: если по рендеру не узнать Леонидова/Лисицкого — работа не принята.

## 6. Ограничения

- **Площадка:** GitHub Pages, проект-страница → сайт живёт в подпапке `/atelier/`.
  Все внутренние ссылки и ассеты — относительные; никаких корневых `/assets/...`.
- **Сеть:** ноль внешних запросов при загрузке (шрифты, иконки, скрипты — локальные).
  Внешние `href` в тексте (GitHub, Telegram, почта) разрешены — это контент, не ассеты.
- **Шрифты:** Unbounded, Golos Text, Martian Mono — SIL OFL, самохостинг WOFF2,
  сабсет кириллица + латиница + цифры + пунктуация. Лицензии кладутся в `dist/fonts/`.
- **Совместимость:** CSS Subgrid — Baseline; фолбэк на вложенный Grid через `@supports`.
- **Доступность:** WCAG 2.2 AA как минимум: SC 1.4.3, 1.4.11, 2.4.7, 2.3.3, 2.5.8.
- **Профиль:** сборка и приёмка локальные; публикация — через GitHub API (git push
  запрещён гейтом профиля).

## 7. Рассмотренные подходы

1. **Контент-граф + свой сборщик (выбран).** `content/*.json` → `build/build.mjs` →
   `dist/*.html`. Ноль зависимостей: сборка идёт на голом node, в CI не нужен `npm ci`.
   Полный контроль над subgrid, SVG-генерацией и четырьмя палитрами; гейты меряют
   готовый `dist`. Цена: свой мини-шаблонизатор (~500 строк) и пересборка всех страниц
   при правке общей рамки. Это цена, которую уже платит консоль, и она приемлема.
2. **Astro.** Коллекции контента и MDX удобны для будущих статей, но тянут node-тулчейн
   и зависимости в сборку — ровно то, от чего док отказывается ради «минимума кода»;
   плюс лишний слой между контрактом и рендером при проверке геометрии.

Выбран подход 1 (решение заказчика, 26.11.2026).

## 8. Решения, принятые заказчиком

- Оба сайта существуют параллельно; atelier — отдельный репозиторий GitHub Pages.
- Стек: контент-граф + собственный сборщик без зависимостей.
- Объём v1: фазы 1–3 дока (§5.3), интерактив — вторым заходом.

## 10. Контракт дизайн-кода (числа)

### 10.1 Носители

Токены — строго из дока (§4.1), без правок значений:

| Токен | void | cyanotype | chiaroscuro | vellum |
|---|---|---|---|---|
| `--bg` | `#0B0C0E` | `#002B49` | `#141416` | `#F4F1EA` |
| `--surface` | `#131519` | `#00365C` | `#1E1F22` | `#E9E4D9` |
| `--fg-primary` | `#F1EFE9` | `#F2F7FB` | `#ECE6DA` | `#121316` |
| `--fg-secondary` | `#A5A8B0` | `#A7CBE4` | `#A7A39A` | `#4B4E56` |
| `--line-structural` | `#646973` | `#6FAFD6` | `#706D66` | `#787B82` |
| `--line-grid-decor` | `#23262E` | `#164A6E` | `#2B2C30` | `#D5CFC2` |
| `--accent-primary` | `#FF533D` | `#FFCA5C` | `#E5B96B` | `#BD2B1C` |
| `--accent-secondary` | `#E0B354` | `#6EE2FF` | `#E66A4E` | `#003153` |

Кристаллические акценты Таута (`#2FE09B`, `#5CA4FF`, `#FF5C8A`, `#FFB84D`) — только
внутри тёмных носителей (`void`, `cyanotype`, `chiaroscuro`), только как рефлексы в
графике, никогда как текст или граница контрола; на `vellum` запрещены.
Прогрессивный слой `oklch()` и `color-mix(in oklch, …)` — внутри `@supports`.

### 10.2 Типографика

- Дисплей: **Unbounded** (variable 200–900), кириллица + латиница.
- Текст: **Golos Text** (variable, 400–900), строка ≤ 65ch, `line-height: 1.7`.
- Технический: **Martian Mono** (variable wdth+wght), `tabular-nums` для чисел и штампов.
- Шкала от 16px с шагом 2^(1/4) = 1,1892:
  `11.31 · 13.45 · 16.00 · 19.03 · 22.63 · 26.91 · 32.00 · 38.05 · 45.25 · 53.82 · 64.00`.
- Роли: body 19.03, лид 22.63, H3 26.91, H2 32.00, H1 45.25 (мобильный — на две
  ступени ниже), дисплей главной 64.00 desktop / 45.25 mobile. Метки/координаты 13.45,
  микро-метки 11.31.
- Трекинг: CAPS 0.08em, заголовки 32px+ −0.01em, дисплей −0.02em. Веса: 400/500/700.
- Только две гарнитуры одновременно на экране в прозе (Golos + Martian); Unbounded —
  заголовки. Заголовки без точки в конце.

### 10.3 Сетка

- 12 колонок ≥1200px, 6 колонок 768–1199, 4 колонки <768; сквозной `subgrid` для
  карточек и текстовых колонок.
- Поля страницы: 32 / 24 / 20 px; желоб: 24 / 20 / 16 px.
- Буквенные оси A–L над сеткой на desktop; порядковые отметки по вертикали в штампе.
- Реперные крестики 5×5px в узлах пересечения осей — только `aria-hidden`, цветом
  `--line-grid-decor`.

### 10.4 Линии и углы

- Толщины: 1px тонкая (`--line-structural`), 1.5px основная, 2px акцентная.
- Осевая штрихпунктирная: `stroke-dasharray="12 4 2 4"`.
- Окончания выносок: точка 4×4 — внутри контура; стрелка — на границе; без символа —
  размерная линия.
- Углы рассечения секций и конструктивных диагоналей: 15°, 23,5°, 30°. Наборный текст
  всегда 0°.
- `border-radius: 0` везде, кроме геометрически круглых элементов (сфера, узлы, радиальные
  индикаторы) — там `50%`.

### 10.5 Планометрия (язык схем)

Проекции — по доку (§3.2): истинная изометрия `rotateX(54.7356deg) rotateZ(45deg)` при
`perspective: none`, коэффициент осей 0,8165; планометрия — горизонталь 45° без искажения
угла, Z в масштабе 1:1. Схемы проектов генерируются сборщиком: слои (3–5) поднимаются
друг над другом с зазором 28px, каждый слой — параллелограмм в планометрии со своими
узлами и подписями по ISO 128.

### 10.6 Движение

Только `opacity` и 2px-сдвиги, 120–240 мс, `cubic-bezier(0.2, 0, 0, 1)`.
При `prefers-reduced-motion: reduce` — всё мгновенно. Никаких вращений сцены в v1.

## 12. Компоненты

1. **Планшет проекта** (`plate`): верхняя строка — индекс, статус, годы, закрытость;
   центр — SVG-планометрия слоёв; низ — название, однострочный тезис, `ОТКРЫТЬ ЧЕРТЁЖ ↗`.
   Наследует колонки `subgrid`.
2. **Переключатель «Конструктив / Контекст»** (`mode`): два состояния досье.
   Контекст — проза + метрики; Конструктив — только схема, таблица спецификаций, стек,
   граф зависимостей. Состояние — `data-mode` на `<article>`, сохраняется в URL-хэше
   (`#constructive`), работает без JS (оба блока в DOM, видимость по атрибуту).
   **Источник прозы:** раздел проекта в `README.ru.md` / `README.md` из Open_space
   (у 12 из 14 он уже размечен как «Проблема / Подход»). Тексты переносятся с
   сокращением, без добавления фактов; ссылки и таблицы сохраняются, растровые картинки
   (`screenshots/*.png`) отбрасываются. Поэтому переключатель работает на всех 14 досье.
3. **Носитель** (`medium`): 4 кнопки в штампе + `data-medium` на `<html>`; значение из
   `localStorage`, дефолт по `prefers-color-scheme`; на всех страницах одинаково.
4. **Штамп** (`titleblock`): наименование площадки, носитель, язык, упрощённый режим
   (reduced motion), ссылки, номер релиза `v1.<build>`, хеш сборки, `МАСШТАБ 1:1 · ЛИСТ 01`.
5. **Линейка масштаба** (`ruler`): правый край, отметки разделов 00–05, текущий раздел
   подсвечен через `:target`/позицию; без JS-перехвата прокрутки.

Все интерактивные элементы: `:hover` и `:focus-visible` с явным откликом, контур
фокуса 2px `--accent-primary` с офсетом 2px, зона нажатия ≥ 44×44 на мобильном.

## 13. Контент

Источник — `workspace/lcars-v6/content/site-full.json`. Маппинг:

- `site.name/role/availability/location/timezone/email/github/linkedin/cv` → главная, контакт, штамп.
- `site.about[]` → `/about/`; `site.record[]` → карьерная запись; `site.facts[]` → таблица.
- `projects[]` (14) → планшеты и досье: `title`, `summary`, `metrics[]`, `stack`,
  `link`, `confidentiality`; проза досье — из раздела проекта в README Open_space.
- **Приоритет источников:** число из `metrics[]`/`results[]` (site-full.json) главнее
  числа из README; при расхождении побеждает site-full.json, расхождение печатается
  в отчёте приёмки, а не правится молча. Формулировки — из README, дословно или сжато.
- `site.services[]` → блок «что делаю» на `/about/` (3 позиции).
- `site.more[]` → ссылки в контакте.
- Поля `metrics` и `results` не пересчитываются и не округляются — берутся как есть.
- Пропуск: `media[]` (PNG-скриншоты) не используется — растровые изображения запрещены.
- В контенте есть разметка: `**жирный**`, `` `код` `` и `[текст](url)` (9 строк EN + те же
  в RU). Шаблонизатор поддерживает ровно эти три правила, всё остальное экранируется;
  длинные URL и токены переносятся `overflow-wrap: anywhere`, ссылки не ломают сетку на 390.
- `problem/approach/results` заполнены у 3 проектов из 14 (см. §12.2); `approach[]` —
  список шагов, он же служит слоями схемы для этих трёх досье.

Тексты манифеста (2 тезиса) пишутся заново на основе формулировки сайта
«системы, которые доказывают свою работу»; утверждаются заказчиком в первом рендере.

### 13.1 Граф технологий и слои схем

`stack` в контенте — свободная строка через `·` и `+` (73 сырых токена, среди них составные:
«React 18 + TypeScript + Vite + Tailwind»). Чтобы `/stack/` и планометрия не были выдуманы,
вводится один нормализующий проход, результат которого лежит в `content/stack.json` и
проверяется глазами один раз:

1. **Нормализация:** строка режется по `·`, `+`, `/`; версии снимаются в поле `version`;
   дубликаты сводятся к каноническому имени (`Node.js` = `Node 20+`; `PostgreSQL 17` =
   `PostgreSQL`). Ожидаемый результат — 40–50 узлов.
2. **Слой узла** (единственная классификация, задаётся вручную по правилу):
   `ЯЗЫК` — язык/рантайм; `ДАННЫЕ` — хранилища, форматы, протоколы данных; `ИНФРА` —
   платформа, деплой, CI, ОС; `ИНСТРУМЕНТЫ` — библиотеки, фреймворки, утилиты.
3. **Рёбра** — только фактические: узел связан с проектом, если токен встречается в его
   `stack`. Ребро «узел—узел» рисуется, когда два узла встречаются в одном проекте;
   толщина — по числу общих проектов. Никаких связей «по смыслу».
4. **Слои планометрии.** Планшет показывает слои по роли из стека проекта (3–5 слоёв,
   подпись «СЛОИ ПО РОЛИ»). Досье с `approach[]` показывает слои по шагам замысла
   (подпись «СЛОИ ПО ЗАМЫСЛУ»). Других источников слоёв нет — архитектурные
   декомпозиции для 11 проектов не выдумываются.

## 14. Сборка

```
atelier-v1/
  content/site.json           сайт: имя, роли, биография, факты, контакты, ссылки
  content/projects/*.json     14 проектов (по файлу)
  content/stack.json          слои и узлы графа технологий
  build/build.mjs             сборщик: читает контент, пишет dist/
  build/tpl/*.mjs             шаблоны: layout, home, work, dossier, stack, contact
  build/axonometry.mjs        генератор планометрических SVG-схем из слоёв проекта
  src/css/*.css               tokens, base, grid, components, mediums
  src/js/site.js              носитель, режим досье, координаты указателя (≤10 КБ)
  src/fonts/*.woff2           сабсеты + OFL-лицензии
  gates/*.py                  6 гейтов приёмки (см. §15)
  shots/                      рендеры
  dist/                       результат сборки
```

Порядок сборки: контент → токены → CSS (склейка в `dist/assets/site.css`) → страницы
(38 HTML: 19 RU + 19 EN) → SVG-схемы инлайном → `dist/sitemap.xml`, `robots.txt`.
Сборщик детерминирован: одинаковый вход → одинаковый `dist` (хеш в штампе считается
от контента, не от времени).

## 15. Приёмка (машинные гейты, fail-closed)

| Гейт | Что проверяет | Порог |
|---|---|---|
| `check_contrast.py` | вычисленные стили в браузере по каждому носителю | fg-primary/bg ≥ 7.0; fg-secondary ≥ 4.5; line-structural vs bg и vs surface ≥ 3.0; accent-primary и accent-secondary ≥ 4.5 при использовании как текст, ≥ 3.0 как графика (минимум по факту — chiaroscuro accent-secondary 5,73) |
| `check_layout.py` | Playwright 1440×900 и 390×844, все 38 страниц | `scrollWidth == clientWidth`; 0 обрезанного текста; 0 перекрытий соседних блоков; зона нажатия ≥ 44×44 на 390 |
| `check_grid.py` | выравнивание секций по 12-колоночной сетке на 1440 | левые/правые края секций совпадают с треками ±1px |
| `check_weight.py` | вес по типам и по типу страницы | HTML: реестр `/work/` ≤ 60 КБ, досье ≤ 45 КБ, прочие ≤ 30 КБ; CSS ≤ 45 КБ; JS ≤ 10 КБ; шрифты ≤ 240 КБ; первая загрузка ≤ 400 КБ без сжатия |
| `check_copy.py` | авторская копия интерфейса (nav, метки, заголовки, кнопки, манифест) | 0 em dash в латинице; 0 точки в заголовках; `text-transform: uppercase` только у `.dwg`; 0 филлеров. Импортированный контент проверяется отдельно и не переписывается |
| `check_static.py` | ассеты и офлайн | 0 растровых файлов в `dist`; 0 внешних `<script|link|img>`; лицензии шрифтов на месте; `lang` на `<html>`; skip-link; `prefers-reduced-motion` присутствует |

Определения к гейтам: `.dwg` — только чертёжные подписи (индексы, статусы, единицы,
буквы осей, поля штампа): Martian Mono, 11.31–13.45px, трекинг 0.08em. Прописные
аббревиатуры в тексте (`API`, `DXF`, `NDA`, `RAG`, `CI` и ещё 31 токен из контента) —
естественный регистр, гейтом не ловятся. Em dash в авторской латинской копии запрещён;
в импортированном тексте проектов остаётся как есть и печатается в отчёте, решение о
правке — за автором.

Плюс рендер-доказательство: `shots/` — главная в 4 носителях × desktop/mobile,
реестр, одно досье в обоих режимах. Числа (вес, контрасты, размеры) — в отчёте приёмки.

Гейт меняется только новой версией спеки; подгонять порог под результат запрещено.
